# 使用済みテストの移行準備と読取専用の接続確認

対象は仮想研究のみ。今回の追加は、旧記録から**共有台帳の候補を作る**処理と、既存保存先を**読むだけ**の確認処理。実際の台帳作成・更新、認証情報の作成、権限変更、定期実行、既存EAの変更はしない。

## 旧ローカル記録の移行案

`scripts/plan-research-migration.mjs` は、明示的に列挙した旧 `audit.jsonl` のハッシュ鎖と予約の識別子・時刻を確認する。成功・失敗・中断にかかわらず、`holdout-reserved` の消費済み区間を移行案に残す。

- 元の実験ID、要求・エンジン・テストのハッシュ、区間、予約時刻を保持する。移行専用の試行IDは元の識別子から決定する。
- 旧結果を新エンジンの成功と扱わず、移行案ではすべて `reserved` にする。完了記録や採用資格を引き継がない。
- 同一記録のコピーは区別して記録しつつ予約だけを一つにする。相反する記録、重複区間、同じテストハッシュの再利用、壊れた監査鎖は停止する。
- 消えた記録は無視しない。根拠と、消費済み範囲を覆うUTCミリ秒の `consumedBefore` を明示する。該当時刻より前は全体として使用済み扱いになる。
- 共有台帳導入後のローカル記録から共有予約を再構築しない。この場合は元の権威ある共有台帳が必要。
- 入力ファイルは変更せず、出力は `reports/` 内の新規JSONだけ。上書きとシンボリックリンク経由の出力を拒否する。

入力例。`auditPath` はmanifestのあるディレクトリからの相対パス、または絶対パス。

```json
{
  "ledgerId": "fx-research-example-ledger",
  "sources": [
    {"sourceId": "legacy-host-a", "auditPath": "old-state/audit.jsonl"}
  ],
  "missingSources": []
}
```

欠けた記録がある場合だけ、`missingSources` に `sourceId`、`consumedBefore`、`evidence` を入れる。推測だけの短いcutoffを使わず、範囲が不明なら移行を止める。単位は秒ではなくUTCミリ秒。

```bash
node scripts/plan-research-migration.mjs \
  --manifest=PRIVATE_MANIFEST.json \
  --output=reports/autonomy/migration-plan.json
```

出力には台帳候補、元記録のハッシュ、インベントリ、最も早い次回テスト開始時刻、未解決事項、計画全体のハッシュがある。`activationReady` は常に `false`。このツールは、列挙した記録が全履歴であることや、バックアップの真正性・完全性を保証しない。外部の信頼できる最終ハッシュと照合しない限り、正常なprefixだけを残した末尾切落としは検出できない。台帳候補をそのまま保存して本番を有効化してはいけない。

`consumedBefore` だけで保護した場合、旧ディレクトリの予約との厳密な照合はできない。旧状態は保存したまま、新しい成果物ディレクトリを使う。共有台帳の既存内容を初期化・置換する許可にはならない。

## 既存共有保存先の読取専用確認

`inspectResearchLedger` は接続済みのリポジトリ情報取得とファイル読取を受け取り、次を確認する。

1. 設定は `repository`、`branch`、`path`、`ledgerId` のみ。認証情報を設定JSONに入れない。
2. 指定リポジトリの識別子と非公開性、既存のread/write権限がmetadataで確認できること。公開保存先では台帳本文を読まない。
3. 台帳の識別子・形式と、二度の読取間で過去へ戻っていないこと。

書込APIは呼ばない。成功しても条件付き更新の動作、障害時の保持、管理者による巻戻し防止、過去記録の移行完了を保証しない。これらはブロッカーとして残し、`activationReady` は `false` のまま。実サービスでの競合・障害試験は、承認された専用の非公開領域で別に必要。

## 今回の確認

- 復元した既存の私的研究チェックポイントで、316ファイルの保存済みハッシュ、10件の監査イベント、9件の成果物参照を検証した。
- 以前の33観測スモークテストから、使用済みの最終区間を一件、正確な識別子とともにローカル移行案へ保存した。価格データ・履歴・移行案は公開コードに含めない。
- 接続済みGitHubの読取確認では、FXコードのリポジトリは公開。専用の非公開FX研究台帳の保存先はまだ確認できていない。別用途の非公開プロジェクトを流用していない。
- 遠隔台帳の作成・書込やジョブ有効化は未実施。観測データを使う新しい研究実行も行っていない。

合成データによる外側リプレイの検証範囲は [合成の因果的な外側リプレイ](synthetic-causal-outer-replay.md) を参照。こちらも実市場の収益性や連続運用の証拠ではない。
