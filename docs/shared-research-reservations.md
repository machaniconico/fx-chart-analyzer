# 仮想研究の共有予約台帳

## 実装済みの範囲

`runResearchCycle` は非同期になり、ローカル成果物ディレクトリとは別に `reservationStore` を必須で受け取る。各実験は、学習・選択の計算に入る前に共有台帳へテスト区間を予約する。別プロセス・別ディレクトリでも、同じ台帳を参照する限り二重利用を拒否する。

- 台帳の版を条件にした compare-and-swap を使う。GitHub Contents API の場合は取得した blob SHA を更新の `sha` に指定する。
- 競合が「書かれていない」と確認できる場合だけ再読込みして再判定する。他の予約を保持し、最大8回で停止する。
- 応答喪失やタイムアウトは成功扱いにしない。共有台帳を読み直し、自分の一意な試行IDを含む予約が完全に一致するときだけ進む。未確認なら再送せず停止する。
- 予約は期限切れにならない。中断した予約の引継ぎ、削除、解放、自動再実行はしない。新しい実験には、すべての使用済み区間より後の未使用テストが必要。
- 要求は最初の非同期待機より前に複製する。待機中の入力変更で、予約済みハッシュと実際の計算が食い違わない。
- 結果ファイルを書いてfsyncし、そのハッシュを共有台帳の自分の予約に条件付きで記録した後に、ローカル完了イベントを書く。共有完了を確認できなければ成功を返さない。
- 保存済み結果の利用にも共有台帳の再読込みが必要。実験ID、要求・エンジンのハッシュ、試行ID、結果ハッシュ、ローカル記録の一致を確認する。別ディレクトリに成果物がなければ再計算せず停止する。
- 共有完了後にローカル最終イベントの記録だけが失敗した場合は、照合済みの準備済み結果を再利用できる。ただし強制終了で残ったローカルロックを自動削除しない。
- 台帳の識別子、形式、版、ハッシュ、重複、期間順序、状態遷移を検査する。既知の予約の削除・改変・完了取消しは拒否する。予約処理のコードも実験のエンジンハッシュに含む。

共有台帳にはハッシュ、時間区間、試行ID、状態だけを保存する。価格データ、要求全体、成績の明細、認証情報は送らない。実験結果は引き続きすべて `hold`。実口座接続、注文、採用、デプロイ、ジョブ有効化は追加していない。

## 保存先の契約と有効化条件

本番用の共有保存先は**未作成・未接続**。実観測データの実行は、保存先がなければ停止する。今回確認したのは実装、隔離した合成テスト、既存コネクタの条件付き更新機能であり、実サービスへの永続化試験は行っていない。

有効化には次が必要。

1. 承認された非公開の保存先を特定する。GitHubなら、専用の既存ブランチ、ファイルパス、固定の `ledgerId` を、すべての研究実行環境で共有する。台帳専用の領域を使い、コードPRや公開市場データに混ぜない。
2. 読書き権限、保持・復旧手段、単一の条件付き更新という性質、並行更新時の応答を確認する。プロバイダ障害時は停止する。第三者が台帳を巻き戻せる構成を安全な運用と呼ばない。
3. **旧ローカル台帳の予約を移行する。** 成功・失敗・中断を問わず使用済み区間を保存する。移行できない履歴がある場合は、既知の使用範囲を覆う保守的な `consumedBefore` を設定し、それ以前をすべて使用済みとする。過去の33観測の確認実験も対象。空の台帳へ移って同じデータを新規扱いしない。
4. 実価格を使わない隔離した遠隔試験で、競合、応答喪失、異常終了、再照合を確認する。実運用の台帳を試験のために削除・巻き戻ししない。
5. 以上の確認後にだけ実観測データの実行を接続する。定期実行の有効化は別の判断とする。

`reservationGenesis(ledgerId, importedReservations, consumedBefore)` は初期文書を作るだけの関数。実行時に保存先を新規作成・再初期化する機能はない。既存ファイルが見つからない、権限がない、JSONが壊れている、台帳識別子が違う場合は停止する。

旧ローカル記録がある実行ディレクトリでは、その予約が共有台帳にも存在することを必須とする。旧エンジンの結果を新エンジンの成績へ読み替えない。過去の完了記録を移行する際に結果の完全性を確認できなければ、使用済みの予約として保持する。

## 接続方法

`createGitHubReservationStore` は、既存の接続済み `readFile` / `updateFile` 関数を受け取るアダプター。読み取りは `repository_full_name, path, ref`、更新は `repository_full_name, branch, path, sha, content, message` を渡す。コネクタの `structuredContent.content` と `sha` を使い、更新後は必ず再読込みする。明示的なHTTP 409だけを安全に再試行できる競合とし、分類できないエラーは未確認として照合・停止する。

単体CLIには、既に許可・設定済みの短命な `GITHUB_TOKEN` を実行時に受け取るHTTP経路もある。認証情報の作成・取得・保存・権限追加は行わない。接続済みコネクタからトークンを抽出する機能はない。新しい認証設定が必要なら、別途適切な承認が必要。

台帳設定JSONは次の4項目だけ。認証情報を入れない。

```json
{
  "repository": "OWNER/PRIVATE_RESEARCH_STATE",
  "branch": "research-state",
  "path": "ledger/reservations.json",
  "ledgerId": "REPLACE_WITH_VERIFIED_LEDGER_ID"
}
```

```bash
# 合成データの隔離デモ。ローカル状態は市場の証拠ではない。
node scripts/run-virtual-research.mjs --demo reports/autonomy/synthetic-demo

# 保存先と過去履歴の移行を確認し、既存の認証設定がある場合だけ:
node scripts/run-virtual-research.mjs REQUEST.json reports/autonomy/research-state LEDGER_CONFIG.json
```

CLIは非公開リポジトリと台帳の存在を読み取りで確認してから実行する。保存先が未設定でもローカル方式へフォールバックしない。終了コード3は実験完了・採用保留、2はエラー。`--demo` のファイル保存方式は合成テスト専用で、実観測データには使えない。

## 検証と残る限界

共有予約の24テストに、独立した作業ディレクトリの競合、別プロセス同時実行、予約直後／完了書込み前／完了書込み後のSIGKILL、未確定の応答、上書き拒否、過去履歴の遮断、入力変更、準備済み結果の照合を含める。GitHubのテストは模擬トランスポートであり、実サービス試験の代わりではない。

ファイル版は、ファイルfsync、原子的rename、親ディレクトリfsyncを使う**合成テスト用の参照実装**。ネットワークファイルシステムの分散ロックや、実サービスの電源断・災害復旧を保証しない。ローカル成果物の紛失・強制終了によるロック残留も自動修復しない。所有者・管理者による台帳改変への暗号学的な防御ではない。

共有予約が実装されても、外側の時系列評価、代表的な長期データ、資金調達費、流動性、証拠金、相場分類・切替・配分の検証は未完了。収益性や実運用可能性を示すものではない。
