# 相場別の仮想EAを自律的に検証・改善する設計

更新: 2026-11-11。対象: 仮想研究のみ。実口座への注文、MQLの自動配布、既存EAの差し替え、デプロイは行わない。

## 1. 目標

**常に市場を監視し、優位性を確認できたEAだけが新規エントリーする。全EAがノーポジションでも正常。**

相場の種類ごとに複数候補を用意し、データ確認 → 相場判定 → 候補選択 → 共通資金による仮想実行 → 評価 → 改善候補の生成 → 独立検証を繰り返す。利益や常時ポジションは保証しない。評価基準は稼働率や取引回数だけでなく、コスト控除後の成績、最大損失、安定性、見送るべき場面で見送れたか。

## 2. 今回の実装範囲と未完部分

実装済み:

- 仮想専用の候補IDとコード・設定・データ・ポリシーのハッシュ、追記型監査レコード。
- 学習／選択／独立テストの時間境界と、ラベル・ポジション終了時刻による除外。
- 確定足だけを使う暫定相場分類、過去時点に既知だった為替換算値、切替の抑制、全候補待機。
- 独立検証の証跡を要求する審査関数。結果は新しい仮想観察への候補資格まで。
- 共通資金、同時ポジション、通貨別リスク、含み損、日次損失、ドローダウンを扱うイベント形式の仮想口座。
- 既存44戦略の読み取り専用監査と、上書きしないレポート出力。
- 小幅かつ最大20件のトレンド／レンジ候補生成、学習・選択・凍結後テスト、2倍費用ストレス、全試行記録、独立テストの一度限り消費、排他制御と同一実験の再実行防止。

**まだ実装していないもの:** OHLCから執行イベントを正しく生成する接続層、実データで候補生成から切替までを再学習する外側の検証、仮想観察から共通口座への自動採用、継続ジョブ、画面表示。このため「自律改善が運用開始済み」「44戦略の収益性を検証済み」とは扱わない。審査関数の真偽値は後続の検証器が計算・証明すべき入力であり、この関数だけで検証の実施を証明するものではない。

新規コードは既存処理から呼ばれていない。既存の7採用EA・37観察EA、確定履歴、日次ワークフロー、PR #166 はそのまま。

## 3. 現状で先に解消すべき問題

基準コミット: [38de7cb](https://github.com/machaniconico/fx-chart-analyzer/commit/38de7cbfe5e5da23eac3ba7b3822098aea004ae6)

1. `tune-virtual-strategies.mjs` の validation は候補の採否に使われる。未使用テストとは呼べない。現在の walk-forward は、選択後のパラメータを区間別に確認するもので、生成・選択まで各時点で再実行する外側の検証ではない。
2. 現在の結果は各EAに独立の初期残高を置く。合計損益を単一口座の利益と見なすことはできない。
3. `backtest.ts` の換算用 `nearestBar` は未来のUSDJPY足を選ぶ場合があり、同時刻の足の終値もエントリー始値時点では未知。EURUSD/GBPUSDのロットと円換算評価を新しい因果的な経路で再検証する必要がある。
4. 旧フォワードの同世代設定変更を新世代の証跡に流用しない。設定を変える場合は必ず新しい登録時刻・世代・履歴を作る。
5. 日次更新と最大96時間の表示用鮮度判定は、時間単位の新規エントリー判断に十分ではない。新しい口座はより厳しい鮮度判定を別途持つ。

既存成績を消したり書き換えたりせず、legacy/reference として残す。新方式の成績は別の世代・別の台帳に記録する。

## 4. 相場判定とEAの役割

| 相場 | 主候補 | 初期の扱い |
| --- | --- | --- |
| 上昇・下降トレンド | MA、ADX、押し戻り追随 | トレンド方向を区別して観察 |
| 安定レンジ | RSI、BB等の平均回帰 | 低コスト・十分な流動性のみ |
| 収縮後のブレイク | Donchian、BBブレイク | 独立した候補群として追加 |
| 急変・指標前後・高コスト | まず待機 | 無理に稼働EAを割り当てない |
| 切替中・不明・欠損 | 待機 | 既存ポジションの決済管理は継続 |

最初の分類器は確定足の変動幅・方向効率を使う保守的な固定ルール。学習済みの精度や確率を意味しない。指標カレンダー、実際のスプレッド、データ品質が不明なら新規は見送る。

EAを選択しただけでは注文にならない。選ばれたEA自身のエントリー条件、時間帯、ニュース、コスト、口座リスクの全条件が必要。切替は既存ポジションの担当EAを変更せず、新規エントリー権限だけに作用する。判定が揺れる場合は最低維持時間と十分なスコア差を要求する。停止したEAや不適格になったEAには維持時間を適用しない。

## 5. 時系列の検証設計

### 5.1 役割を三つに分離

- 学習区間: パラメータ、特徴量、相場分類器の学習。
- 選択区間: 候補の比較、EA組合せ、切替条件、資金配分の選択。何度見ても「未使用」には戻らない。
- 独立テスト区間: 全設定を固定した後、一度だけ評価。結果を見て直したらその区間は次回の学習資料に格下げし、新しいテスト区間を待つ。

目安は最低2年の高品質履歴。固定の60/20/20分割だけで合格とはしない。異なる相場・季節を含む3つ以上の外側時系列区間と、最後の封印区間を設ける。履歴不足や取引不足なら合格基準を緩めず「証拠不足」にする。

### 5.2 外側リプレイ

各外側区間の開始時点で、その時点より前の情報だけを使って、候補の生成、EA選択、相場分類器、切替閾値、配分ルールまで作り直す。その固定システム全体を次の未使用区間で共同運用する。EA単体だけを未来から選んで並べた成績は禁止。

同じ基準日、同じデータ、同じ費用、同じリスク予算で、(a) 待機、(b) 固定EA、(c) 切替なし固定組合せと比較する。切替に追加価値がない場合は単純な構成を残す。

### 5.3 漏洩防止

- 時刻はUTC、半開区間 `[start,end)`。OHLC時刻が始値時刻なら、情報が利用可能になるのは足の終了後。
- 売買ラベルや保有期間が次の区間へまたがる標本を除外する。単に数行空けるだけでは不十分。保有期間上限がなければ実際の決済時刻で除外する。
- embargoは最大ラベル／保有重複に基づき事前固定。指標のウォームアップは過去のみ許すが、その期間の利益をテスト成績へ加えない。
- シグナルを確定した同じ終値で約定させない。最初の後続の執行可能気配を使う。
- 為替換算も確定足・as-of既知値のみ。現在足の終値や未来のnearest値を使わない。
- 経済カレンダーは当時公表済みの時刻・情報だけ。後日の修正値を過去に戻さない。
- 未来のデータを変更・追加しても、それ以前の分類、選択、サイズ、損益が変わらないテストを必須にする。

## 6. 共通仮想口座

全EAに同じ初期残高を二重配分しない。口座は一つ、各EAは注文意図を提出するだけ。

初期の研究用候補設定（実運用推奨値ではない）:

- 1取引の計画損失: 純資産の0.25%以下。
- 同時保有: 2件以下、全体の残余ストップリスク1%以下。
- 同一通貨のリスク: 0.5%以下。JPY関連が重なるケースもまとめる。
- 日次損失1%、高値からの損失5%で新規停止。実際の閾値は実験開始前に固定。
- 最小ロットへ切り上げると予算を超える場合は見送る。
- 同時刻は気配更新 → ストップ → 依頼済み決済 → 固定優先順位の新規審査。逐次更新した共通純資産でサイズを再計算。

含み損と出口コストを含む純資産で判定する。利益が出たEAだけの残高を使って他の損失を隠さない。ストップは保証ではなく、窓開けでは観測気配に基づく大きな損失を認める。データが古い場合に架空の価格で強制決済しない。

現在のイベント実装は手数料・スリッページを持つが、流動性、証拠金強制決済、スワップ／資金調達費は未実装。これらを含めない実験は採用用成績に昇格させない。コスト1.5倍／2倍、1足遅延、ギャップ、欠損、パラメータ近傍で再試験する。

## 7. 自律改善の状態遷移

`提案 → 学習 → 選択 → 凍結 → 独立テスト → 新世代の仮想観察 → 共通仮想口座候補 → 停止／退役`

- 1回の探索予算は最大20候補。落選・エラーを含め全試行を保存。サイクルを変えて通算試行数を隠さない。
- 初期は登録済み戦略の一部パラメータを小幅変更する。コード生成、自動リスク増加、損失上限の緩和は禁止。
- ID、親世代、変更理由、試行数、データ・エンジン・設定・ポリシーハッシュ、評価期間、費用、棄却理由を保存。
- 採用できる候補がなくても終了成功。「改善なし」は正常で、候補を捏造しない。
- 外側で計100取引以上、3区間以上、各区間コスト控除後プラス、DD上限内などを初期審査契約とする。これだけで収益性の統計的保証とはしない。区間別結果・依存を考慮した不確実性を併記する。
- 最終テストは一度だけ消費し、勝者だけでなくシステム全体を評価する。
- 新しい仮想観察は実際の登録後から始める。最低60日かつ50取引を初期目安とし、データ不足は待つ。既存EAの古い成績を新ルールの前向き実績に転記しない。
- 共通口座採用は未実装。実装時は最近の仮想成績、集中リスク、コスト耐性を再判定し、段階的に配分する。劣化時は新規停止して決済管理を残す。自動ロールバックも履歴を消さずイベントとして記録する。

監査のハッシュ鎖は誤編集検出であり署名ではない。真正性や排他制御には、保存先権限、単一writer、条件付き書込み、事前凍結したデータ一覧、外部に固定したヘッドハッシュが必要。

## 8. 実行頻度と報告

目標設計:

- 各確定足: データ品質 → 既存ポジション管理 → 相場判定 → 新規審査。
- 日次: 帳尻照合、停滞・欠損・コスト変化、損失停止、試行／世代の整合性を確認。
- 週次: 予算内で改善候補を生成・検証。サンプルが増えていない場合は再探索しない。
- 月次: 相場別成績、待機理由、切替効果、集中リスク、失敗した仮説をまとめる。

重大な欠損・リスク停止・採用候補完成だけを即時通知し、通常結果はまとめる。現在はこの頻度の自動ジョブを有効化していない。既存の日次データ更新に新機能を無断で混ぜない。

## 9. 実装を進める順番と完了条件

1. **今回: 基礎契約、仮想共通口座、読み取り専用監査。** 単体テストと既存全テスト・ビルド。
2. **因果的なリプレイ接続層。** OHLCの確定・執行タイミング、換算、コスト、SL/TP同一足、ギャップを固定。旧エンジンとは世代を分離。未来改変テストに合格。
3. **外側実験ランナー。** 単一の学習／選択／凍結後テストと再実行防止は追加済み。次は過去データだけを受け取る候補生成器を外側の時系列区間ごとに再実行し、相場分類・配分まで含むシステム全体を比較する。
4. **紙上前向き観察。** 再開時の重複注文防止、永続化失敗時の停止、世代の改変拒否、読み取り専用監視から開始。
5. **仮想口座への昇降格と画面。** リスク警告・待機理由・個別/共同成績を表示。運用ジョブはレビュー後に別途有効化。

実口座への接続はこの計画に含めない。

## 11. 継続改善ランナー

ユーザーの継続改善という最終目標に合わせ、土台に加え独立したオフライン実験ランナーを追加した。入力は実際に観測時刻が付いたbid/ask気配と換算値。OHLCの四本値から架空のtick列を作って「実気配」と呼ばない。

候補生成・学習・選択・最終評価・費用ストレス・不採用理由・一度使ったテスト区間を自動記録する。候補群はシード近傍のlookback・保有期間を小幅変更し、予算内でトレンド／レンジ両方を交互に試す。リスタート時の重複試行と証跡上書きを防ぐ。純粋な関数と永続化を分離し、異常中断後は採用ではなく保留する。

この最初の実験ランナーだけでは外側で再学習するシステム全体、ニュース、資金調達費、流動性を証明できないため、数値が良くても自動で共通口座に採用しない。既存OHLCは設計監査に使い、気配データ接続までの不足を明示する。実観測気配の取得・取り込みを小規模に接続した。次は、代表的な長期データを分割保存して同じランナーで評価できることが完了条件となる。現在のインメモリ実装に2年分の全tickをそのまま投入せず、保存・処理の分割と欠損検査を先に設計する。


動作確認用コマンド:

```bash
node scripts/run-virtual-research.mjs --demo reports/autonomy/synthetic-demo
# または、実観測気配の入力JSONを用意した後:
node scripts/run-virtual-research.mjs REQUEST.json reports/autonomy/research-state
```

`--demo` は意図的に作った架空の価格系列であり、市場での収益実績ではない。終了コード3は「実験は完了したが採用は保留」、2は入力／実行エラー。現段階は有効な入力でも常に保留とし、必要な独立検証を省いて昇格しない。

状態ディレクトリを継続して使う。同じ要求は保存済み結果を返し、名前を変えた同じテスト内容、重なる期間、過去に戻るテストを拒否する。テスト区間は学習前に予約するため、中断しても未使用へ戻らない。新しいディレクトリに逃げれば監査の連続性は失われるので、それを新しい証拠として認めない。強制終了で残ったロックは自動解除せず、照合してから対処する。

実装はプロセス中断に対して保守的に停止するが、電源断への完全な永続性や、所有者による台帳改変への防御を保証しない。運用化には共有の改変制限付き保存先と再開時照合を追加する。


## 12. 実気配の取り込みと今回の確認結果

専用コマンド `scripts/capture-research-ticks.mjs` は、USDJPY・円口座・過去の1時間以内に限定する。必ず開始／終了を指定し、研究用の `reports/` に新規保存する。WAF回避、トークン保存、リトライは無効。拒否されたら停止し、既存のデータ取得経路や公開データを書き換えない。

```bash
node scripts/capture-research-ticks.mjs --from=2026-11-09T12:00:00.000Z --to=2026-11-09T12:00:10.000Z --output=reports/autonomy/new-private-capture.json
```

Dukascopyの2026-11-09 12:00:00〜12:00:10 UTCの実bid/ask33観測を取得・保存・再読込みできた。時刻やスプレッドは捏造せず、円／円換算は1。4候補を試し、すべて採用保留／棄却として保存された。同じ要求の再実行では追加試行せず、保存済み結果に戻ることも確認した。この10秒だけでは収益性や相場網羅性を評価できない。実データでは候補が選択段階を通らず、最終テストの成績は算出していない。

全テスト1,022件（40ファイル）と本番ビルドに成功。ビルドには既存の大きいbundle警告が残る。追加の144条件で未来の気配追加が過去の意図・約定を変えないことも確認した。現時点の対象は隔離したオフライン研究であり、常駐ジョブ、Webアプリへの反映、実口座取引は未実施。
